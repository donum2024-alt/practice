# Spec — gyeongjaengsa-bigyo (경쟁사 비교)

> 근거: `docs/PRD.md` 기능 4, `docs/domain-story.md`. 선행: `gyeongjaengsa-josa`, `hangmokbyeol-jeongni`.

## Problem Statement

담당자는 경쟁사별 물류 방식, SKU 운영 전략, 강점, 차별화 요소를 한눈에 비교해서 보고 싶어 하지만, 지금은 정리 문서가 경쟁사별로 따로 떨어져 있어 비교하려면 여러 문서를 오가며 옮겨 적어야 한다. 도메인 스토리가 꼽은 세 번째 불편이 바로 이 비교 정리 방식 자체가 오래 걸린다는 점이다.

## Solution

정리를 마쳤거나 진행 중인 여러 경쟁사를 골라 한 화면에 표로 나란히 놓는다. 행은 SKU 수·물류 운영 방식·가격 책정 방식·강점·차별화 요소 5개 항목, 열은 담당자가 고른 경쟁사들이다. 이 화면은 기존 정리 문서(`hangmokbyeol-jeongni`)를 읽기만 할 뿐 새 데이터를 만들지 않는다.

## User Stories

1. 담당자로서, 비교할 경쟁사 여러 곳을 목록에서 선택하고 싶다.
2. 담당자로서, 선택한 경쟁사들의 정리 문서를 표 형태로 나란히 보고 싶다. 행은 항목, 열은 경쟁사.
3. 담당자로서, 경쟁사를 최소 2곳부터 비교할 수 있고, 필요하면 더 추가하거나 뺄 수 있으면 좋겠다.
4. 담당자로서, 아직 항목별 정리를 시작하지 않았거나 일부만 채운 경쟁사도 비교 대상에 넣을 수 있고, 빈 항목은 "정리 안 됨"처럼 표시되길 원한다.
5. 담당자로서, 비교 표에서 경쟁사 이름을 눌러 그 경쟁사의 상세/정리 화면으로 바로 이동하고 싶다.
6. 담당자로서, 경쟁사 목록에서 회장님·경영진이 언급한 회사를 눈에 띄게 구분해서 비교 대상을 고를 때 참고하고 싶다.
7. 담당자로서, 경쟁사 조사 상태(조사중/자료수집됨/정리완료/벤치마킹도출)를 선택 목록에서 보고, 정리가 끝난 곳부터 고르고 싶다.
8. 담당자로서, 비교 화면에 진입할 때 아무 것도 선택 안 된 빈 상태에서 시작해, 필요한 경쟁사만 고르고 싶다.
9. 담당자로서, 선택한 경쟁사 조합을 URL로 공유하거나 새로고침해도 유지되길 원한다.
10. 담당자로서, 비교 표가 길어져도(항목이 많거나 경쟁사가 많아도) 가로/세로로 스크롤해서 편하게 보고 싶다.
11. 담당자로서, 비교 표에서 어느 항목이 "정리 완료" 확정된 내용인지, 아직 초안인지 구분해서 보고 싶다.
12. 담당자로서, 선택했던 경쟁사를 표에서 바로 제외(열 제거)할 수 있으면 좋겠다.
13. 담당자로서, 사이드바 네비게이션에서 비교 화면으로 바로 이동하고 싶다.
14. 담당자로서, 비교할 경쟁사가 하나도 없거나 하나만 선택된 상태에서는 표 대신 안내 문구를 보고 싶다("2곳 이상 선택하세요" 등).

## Implementation Decisions

- **모듈**
  - `app/api/summaries/route.ts` — `GET`(여러 경쟁사의 정리 문서를 한 번에 조회).
  - `app/compare/page.tsx` — 경쟁사 선택 + 비교 표 화면(신규 페이지).
  - `app/layout.tsx` — nav에 '비교' 링크 추가.

- **API 계약**
  - `GET /api/summaries?competitorIds=1,2,3` — 콤마로 구분된 id 목록을 받아, 각 id에 대해 `{ competitor: Competitor, summary: Summary | null }` 배열을 **요청된 id 순서대로** 반환한다. 존재하지 않는 id는 결과에서 건너뛴다(에러 아님). `competitorIds`가 없거나 파싱 결과가 빈 배열이면 400.
  - 경쟁사 전체 목록·상태는 기존 `GET /api/competitors`(선택 UI에서 재사용)로 충분하며 새 엔드포인트를 만들지 않는다.

- **선택 상태 관리** — 서버에 저장하지 않는다. 선택된 경쟁사 id 목록은 URL 쿼리스트링(`/compare?ids=1,2,3`)에 둬서 새로고침·공유 시에도 유지되게 한다(클라이언트 상태 + URL 동기화, 새 DB 테이블 없음).

- **UI**
  - 상단: 경쟁사 선택 영역 — 전체 경쟁사 목록(이름, 상태 뱃지, 회장님/경영진 언급 표시)에 체크박스. 선택 시 URL의 `ids`를 갱신.
  - 하단: 선택된 경쟁사가 2곳 미만이면 안내 문구만 표시. 2곳 이상이면 표 렌더링 — 첫 열은 항목명(SKU 수/물류 운영 방식/가격 책정 방식/강점/차별화 요소), 이후 열은 경쟁사별 정리 내용. 정리 문서가 없거나 해당 항목이 빈 값이면 "정리 안 됨" 텍스트로 표시. 확정된 문서는 열 헤더에 완료 표시를 곁들인다.
  - 표는 `overflow-x-auto` 컨테이너로 감싸 경쟁사가 많아져도 가로 스크롤되게 한다.

## Out of Scope

- 비교 결과를 별도 문서로 저장하거나 내보내기(엑셀/PDF) — 화면에서 보는 것까지만.
- 비교 화면에서 정리 내용을 직접 수정하는 것 — 수정은 `hangmokbyeol-jeongni` 화면에서만.
- 항목 가중치·점수화·자동 순위 매기기.
- 저장된 "즐겨찾는 비교 조합" 관리 — URL 공유로 충분하다고 본다.

## Further Notes

- 이 스펙은 새 테이블을 만들지 않는다. `hangmokbyeol-jeongni`가 만든 `summaries`를 읽기 전용으로 조합할 뿐이다.
- 경쟁사가 삭제되면(정리 문서를 포함해 캐스케이드 삭제됨) 비교 화면의 URL에 그 id가 남아 있어도 `GET /api/summaries`가 해당 id를 조용히 건너뛰므로 화면이 깨지지 않는다.
