# Spec — jeongni-ai-choan (항목별 정리 AI 초안)

> 근거: `docs/PRD.md` 기능 7 (Headline value). `docs/domain-story.md`. 선행: `hangmokbyeol-jeongni`, `jaryo-suchip`.

## Problem Statement

담당자가 가장 번거로워하는 지점은 수집한 자료를 항목별로 옮겨 적는 작업 자체다(도메인 스토리 불편 2, 3번). `hangmokbyeol-jeongni`가 빈 양식을 제공하지만, 그 양식을 채우는 일은 여전히 담당자가 수집 자료를 하나하나 읽고 손으로 옮기는 수작업이다.

## Solution

경쟁사의 수집 자료(`jaryo-suchip`이 모은 것)를 입력으로 받아, AI가 SKU 수·물류 운영 방식·가격 책정 방식·강점·차별화 요소 5개 항목 각각의 초안 문장과 그 근거를 스트리밍으로 생성한다. 담당자는 빈 양식을 채우는 대신 생성된 초안을 검토·수정한 뒤 `hangmokbyeol-jeongni`의 저장/확정 절차로 확정한다. 이 기능은 이미 모인 수집 자료만 입력으로 쓰며, 새로 웹을 검색하지 않는다(웹 검색은 `jaryo-suchip`의 역할).

## User Stories

1. 담당자로서, 항목별 정리 화면에서 "AI 초안 생성" 버튼을 눌러, 지금까지 모은 수집 자료를 바탕으로 5개 항목의 초안을 한 번에 받고 싶다.
2. 담당자로서, AI가 새로 웹을 검색하는 게 아니라 이미 모아둔 수집 자료만 사용한다는 걸 알고 싶다.
3. 담당자로서, AI가 생성하는 동안 진행 상황이 실시간으로 보이면 좋겠다.
4. 담당자로서, 항목마다 AI가 만든 초안 문장과 함께 그 근거(어떤 수집 자료를 바탕으로 했는지)를 보고 싶다.
5. 담당자로서, 어떤 항목은 관련 수집 자료가 부족해 AI가 초안을 만들지 못하면, "자료 부족"이라고 표시되길 원한다(추측해서 채우지 않도록).
6. 담당자로서, AI가 만든 초안이 정리 문서 항목에 바로 채워지되, 저장하기 전까지는 확정되지 않는다는 걸 알고 싶다.
7. 담당자로서, AI 초안을 그대로 쓰지 않고 자유롭게 고친 뒤 저장하고 싶다.
8. 담당자로서, 이미 직접 채워둔 항목이 있다면 AI 초안으로 실수로 덮어써지지 않도록, 항목별로 채택 여부를 고르고 싶다.
9. 담당자로서, AI 초안 생성을 다시 요청하면 이전 초안 대신 새 초안을 받고 싶다(자료가 더 모인 뒤 다시 시도).
10. 담당자로서, 수집 자료가 하나도 없는 경쟁사에서는 AI 초안 생성이 의미 없다는 안내를 먼저 보고 싶다.
11. 담당자로서, AI 실행이 실패하면(claude CLI 오류 등) 에러를 보고 다시 시도하고 싶다.
12. 담당자로서, AI 초안 생성을 진행 중에 중단할 수 있으면 좋겠다.
13. 담당자로서, AI가 제시한 근거에서 인용한 자료의 출처(자료 내용 일부 또는 출처 이름)를 보고, 필요하면 그 자료 원문으로 찾아가고 싶다.

## Implementation Decisions

- **모듈**
  - `app/api/ai/draft-summary/route.ts` — `POST { competitorId }`. SSE 스트리밍. `CLAUDE.md`의 `spawn` + `ReadableStream` + `text/event-stream` 패턴.
  - `app/competitors/[id]/ItemSummarySection.tsx` — `hangmokbyeol-jeongni`가 만든 컴포넌트에 "AI 초안 생성" 버튼과 초안 검토/채택 UI를 추가한다(새 컴포넌트를 만들지 않는다).

- **입력 구성** — 라우트가 `competitorId`로 `competitors`와 그 경쟁사의 `collected_materials` 전체를 조회(없으면 404, 자료가 0건이면 400 + "수집된 자료가 없습니다"). 자료를 `topic`별로 묶어 프롬프트에 포함한다(미분류 자료도 "기타"로 함께 전달).

- **프롬프트** — "다음은 한 경쟁사에 대해 이미 수집된 자료다. 이 자료만 근거로 SKU 수, 물류 운영 방식, 가격 책정 방식, 강점, 차별화 요소 5개 항목의 정리 초안을 작성하라. 새로운 사실을 추측하거나 자료에 없는 내용을 채우지 말 것. 특정 항목에 쓸 만한 자료가 없으면 그 항목은 draft를 빈 문자열로 두고 evidence에 '자료 부족'이라고 적을 것." + 항목별로 묶은 수집 자료 목록(내용, 출처 이름, topic).

- **출력 형식** — JSON 한 덩어리:
  ```json
  {
    "items": {
      "SKU수": { "draft": "...", "evidence": "..." },
      "물류운영": { "draft": "...", "evidence": "..." },
      "가격책정": { "draft": "...", "evidence": "..." },
      "강점": { "draft": "...", "evidence": "..." },
      "차별화요소": { "draft": "...", "evidence": "..." }
    }
  }
  ```
  `items`의 5개 키는 `SummaryItemKey`(`hangmokbyeol-jeongni`) 값과 정확히 일치해야 한다. "JSON 외 다른 텍스트를 출력하지 말 것" 명시.

- **스트리밍·파싱·중단·에러 처리** — `jaryo-suchip`(및 `siljeon-jeonryak`의 AI 라우트)과 동일한 패턴을 그대로 재사용한다: 서버는 줄 단위로 `data: ` 프리픽스를 붙여 전달, 클라이언트는 `data:` 줄을 모아 재조립 후 코드펜스 제거 + 첫 `{`~마지막 `}` 슬라이스 후 `JSON.parse`. `AbortController`로 중단, ENOENT 메시지 등도 동일.

- **검토/채택 UI** — 파싱 성공 시 5개 항목 각각에 대해: draft가 비어 있지 않으면 체크박스(기본 선택)로 "이 항목에 AI 초안 채택" 표시 + draft 미리보기 + evidence 텍스트. draft가 빈 문자열(자료 부족)이면 채택 불가로 표시하고 evidence만 안내로 보여준다. "선택한 항목 반영" 버튼을 누르면 채택된 항목의 텍스트 영역에 draft 내용을 채워 넣는다(기존에 담당자가 써둔 내용이 있으면 덮어쓸지 확인 후 진행). 반영은 화면 상태만 바꿀 뿐, `hangmokbyeol-jeongni`의 기존 저장(`PUT /api/competitors/[id]/summary`) 버튼을 눌러야 실제로 저장된다 — AI 결과의 자동 확정은 없다.

## Out of Scope

- AI가 새로 웹을 검색하는 것 — 그건 `jaryo-suchip`의 역할이며, 이 기능은 이미 모인 자료만 쓴다.
- evidence에 인용된 자료로 원클릭 이동(하이라이트) — 텍스트로 어떤 자료를 참고했는지 설명하는 수준까지만.
- 항목별 초안의 신뢰도 점수화.
- 초안 자동 저장 — 항상 담당자가 반영 여부를 고르고 기존 저장 버튼으로 확정.

## Further Notes

- 이 스펙은 `hangmokbyeol-jeongni`가 이미 만든 저장/확정 파이프라인 위에 얹는 기능이라 새 스키마를 추가하지 않는다.
- `app/api/ai/draft-summary/route.ts`와 `app/api/ai/collect-materials/route.ts`(그리고 `siljeon-jeonryak`의 `draft-strategy`)는 같은 SSE 프레이밍 방식을 공유한다 — 세 번째 구현이므로 공통 헬퍼로 뽑을지는 구현 시 판단(스펙은 강제하지 않는다).
- PRD가 이 기능을 "핵심 도우미"이자 "Headline value"로 명시했으므로(`jaryo-suchip`의 웹 검색과 함께 이 도구의 핵심 가치), 구현 시 초안 품질에 대한 검토(프롬프트 튜닝)에 시간을 더 들일 가치가 있다 — 단, LLM 출력의 내용 품질 자체는 테스트로 검증하지 않는다(별도 원칙, `spec-retire` 유실 화이트리스트 1번 참고).
