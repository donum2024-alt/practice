# PRD — 경쟁사 벤치마킹 검토 도구

> 근거 문서: `docs/domain-story.md`. 용어는 도메인 스토리의 용어 표를 그대로 쓴다.

## Problem Statement

비전전략팀 담당자는 특정 경쟁사(건설자재 유통사)를 조사 대상으로 정하면, 그 경쟁사가 잘하고 있는 부분 — SKU 수, 물류 운영 방식, 가격 책정 방식 등 — 을 홈페이지·뉴스·기사에서 찾아 항목별로 문서나 엑셀에 옮겨 정리하고, 우리가 따라 할 벤치마킹 지점을 뽑아 단계별 실행 전략까지 세운다. 최종 목적은 그 전략을 실제 사업에 반영해 물류비 절감이나 SKU 효율화를 통한 매출 증대 같은 성과를 내는 것이다.

지금은 이 일을 검색과 수작업으로 한다. 담당자가 특히 번거로워하는 세 가지:

- 경쟁사 자료를 찾는 검색이 오래 걸린다.
- 찾은 내용을 항목별로 옮겨 정리하는 작업이 오래 걸린다.
- 경쟁사별 물류 방식·SKU 운영 전략·강점·차별화 요소를 한눈에 비교해서 보고 싶은데, 그렇게 정리하는 방식 자체가 오래 걸린다.

## Solution

비전전략팀 담당자가 혼자 쓰는 내부 도구. 조사할 경쟁사를 등록하면, AI가 웹에서 자료를 모아 항목별 정리 초안을 만들어 준다. 담당자는 초안을 검토·수정하고, 부족한 부분은 직접 찾은 자료를 붙여넣어 보완한다. 정리가 끝나면 여러 경쟁사를 한 화면에서 항목별로 나란히 비교하고, 거기서 우리가 따라 할 벤치마킹 지점을 뽑아 단계별 실행 전략까지 한 도구 안에서 작성한다.

핵심 도우미 두 가지:
- **자료 수집** — 경쟁사 이름만 넣으면 AI가 홈페이지·뉴스·기사를 검색해 자료를 모은다. 검색 시간을 크게 줄인다.
- **항목별 정리 AI 초안** — 수집한 자료를 바탕으로 SKU 수·물류 운영 방식·가격 책정 방식·강점·차별화 요소 항목의 초안을 자동으로 채운다. 담당자는 옮겨 적는 대신 검토·수정만 한다.

## Features

1. **gyeongjaengsa-josa** — 조사할 경쟁사를 도구에 등록하고 목록으로 관리한다. 경쟁사 이름과 간단한 메모, 회장님·경영진이 언급한 회사인지 여부를 입력한다. 각 경쟁사의 조사 진행 상태(조사 중 / 자료 수집됨 / 정리 완료 / 벤치마킹 도출)를 한눈에 본다.

2. **jaryo-suchip** — 등록한 경쟁사별로 자료를 모으는 곳. AI가 경쟁사 홈페이지·뉴스·관련 기사를 웹에서 검색해 찾은 내용을 수집 자료로 쌓아 준다. 담당자는 직접 찾은 기사나 업계 지인·내부 회의에서 얻은 정보를 자료로 붙여넣어 보완할 수 있고, 각 자료의 출처를 남긴다.

3. **hangmokbyeol-jeongni** — 경쟁사 한 곳의 정리 문서. SKU 수, 물류 운영 방식, 가격 책정 방식, 강점, 차별화 요소를 항목별로 적는 양식. 담당자가 수집 자료를 보며 각 항목을 채우고 자유롭게 수정한다.

4. **jeongni-ai-choan** — 수집 자료를 바탕으로 AI가 항목별 정리 문서의 각 항목 초안과 근거를 생성해 스트리밍으로 채워 준다. 담당자는 빈 양식을 채우는 대신 초안을 검토·수정한 뒤 확정한다.

5. **gyeongjaengsa-bigyo** — 정리를 마친 여러 경쟁사를 한 화면에 나란히 놓고 항목별(SKU 수·물류 운영 방식·가격 책정 방식·강점·차별화 요소)로 비교한다. 비교할 경쟁사를 골라 표 형태로 본다.

6. **benchmarking-jijeom** — 정리·비교 내용에서 우리가 따라 할 만한 지점을 벤치마킹 지점으로 뽑아 기록한다. 어느 경쟁사의 어떤 항목에서 나왔는지, 왜 따라 할 만한지를 남기고, 실제 사업 반영 상태(검토 중 / 전략 수립됨 / 사업 반영됨 / 보류)와 결과 메모를 관리한다.

7. **siljeon-jeonryak** — 벤치마킹 지점마다 이를 실제로 실행하기 위한 단계별 실행 전략(프로세스와 단계별 방법)을 작성한다. 단계를 순서대로 추가·편집하고, 벤치마킹 지점과 수집 자료를 바탕으로 한 AI 초안 제안을 받을 수 있다.

## Scope & Priorities

**Core (이 순서로 빌드):**
1. `gyeongjaengsa-josa` — 나머지 모든 기능의 토대(경쟁사 레코드 + 조사 상태 + 목록).
2. `jaryo-suchip` — 경쟁사에 수집 자료를 붙인다. AI 웹 검색이 여기 들어간다.
3. `hangmokbyeol-jeongni` — 경쟁사에 항목별 정리 문서를 붙인다.
4. `gyeongjaengsa-bigyo` — 정리 문서들을 한 화면에서 비교한다.
5. `benchmarking-jijeom` — 정리·비교에서 벤치마킹 지점을 뽑는다.
6. `siljeon-jeonryak` — 벤치마킹 지점에 단계별 실행 전략을 붙인다.

**Headline value:**
7. `jeongni-ai-choan` — `hangmokbyeol-jeongni` 완료 후 그 위에 얹는다. 담당자가 제일 번거로워하는 "항목별 정리" 지점을 푸는 기능이지만, 정리 문서 양식이 먼저 있어야 한다. `jaryo-suchip`의 AI 웹 검색과 함께 이 도구의 핵심 가치다.

`siljeon-jeonryak`의 AI 초안 제안은 있으면 좋은 수준이다. 도메인 스토리에서 전략 작성 자체는 번거로운 지점으로 지목되지 않았으므로, 단계별 양식이 먼저이고 AI 제안은 그 위에 가볍게 얹는다.

## Out of Scope

- **실제 성과 측정** — 물류비 절감액, 매출 증대액을 계산하거나 추적하지 않는다. 전략이 사업에 반영됐는지 여부와 결과 메모를 `benchmarking-jijeom`에 남기는 데까지만.
- **경영진 보고서 생성·발송** — 도메인 스토리가 "경영진 보고 자체는 목적이 아니다"라고 못박았다. 보고용 문서 자동 생성은 넣지 않는다.
- **자료 원본 파일 업로드·저장** — 기사 PDF, 경쟁사 엑셀 등 파일 저장이나 자동 판독은 하지 않는다. 수집 자료는 텍스트로 붙여넣거나 AI가 찾은 내용을 텍스트로 담는 방식만.
- **실시간 경쟁사 모니터링·알림** — 경쟁사 소식을 자동으로 감시하거나 알림을 보내지 않는다. 담당자가 필요할 때 자료 수집을 직접 실행한다.
- **AI 수집·초안의 자동 확정** — AI가 찾거나 정리한 내용은 항상 담당자 검토를 거쳐야 저장된다.
- **사용자 인증·권한 분리** — 담당자 1인 사용을 전제로 로그인이나 접근 제어를 넣지 않는다.

## Further Notes

- **아키텍처**: 템플릿의 3-tier 규칙을 그대로 따른다. Presentation `app/[page]/page.tsx`, Application `app/api/*/route.ts`, Infrastructure `lib/db.ts` + `schema.sql`. `getDB()`는 `'use client'` 컴포넌트에서 호출하지 않는다.
- **상태 모델**: 경쟁사 하나가 `조사 중 → 자료 수집됨 → 정리 완료 → 벤치마킹 도출` 을 오간다. 여러 기능이 이 상태를 공유하므로 `gyeongjaengsa-josa` 스펙에서 상태 값과 전이를 확정한다.
- **AI 기능**: `CLAUDE.md`의 `claude -p` + SSE 스트리밍 패턴을 사용한다. `jaryo-suchip`은 `claude`가 웹 검색 도구를 쓰도록 허용해 실행하고, `jeongni-ai-choan`은 이미 모인 수집 자료를 입력으로 받아 정리한다.
- **타입**: 모든 타입은 `types/index.ts` 단일 관리.
- **기존 예시 코드**: 이 폴더에 들어 있는 가맹점 심사 예시(`schema.sql`, `types/index.ts`, `app/` 하위, 기존 `docs/specs/*`)는 이 프로젝트를 구현할 때 대체된다.
