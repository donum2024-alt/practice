# ADR-0002 — 업무 단계마다 독립된 테이블·엔드포인트를 둔다

## 맥락

자료 수집, 항목별 정리, 여러 경쟁사 비교가 모두 경쟁사 하나에 딸리지만, 각각 생명주기와 갱신 빈도가 다르다(경쟁사는 1회 등록, 자료는 계속 누적, 정리는 초안→확정, 비교는 저장되는 데이터가 아예 없다).

## 버린 대안

- **경쟁사 테이블에 자료·정리 필드를 직접 추가** — competitors 레코드가 비대해지고, 자료처럼 여러 건 누적되는 데이터를 표현할 수 없다.
- **비교 기능을 경쟁사 목록/상세 화면 로직에 바로 포함** — 비교는 여러 경쟁사를 가로지르는 조회라 경쟁사 단건 API와 책임이 다르다.

## 결과

경쟁사는 독립 테이블(competitors)로만 남고, 자료(collected_materials)·정리(summaries)는 competitor_id로 참조하는 별도 테이블로 존재한다. 비교는 새 테이블 없이 summaries를 여러 건 조합해 읽기만 하는 엔드포인트(`/api/summaries`)로 존재한다.
