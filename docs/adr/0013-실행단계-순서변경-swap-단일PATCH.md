# ADR-0013 — 실행 단계 순서 변경은 인접 교환 방식이며 수정과 한 엔드포인트를 공유한다

## 맥락

담당자가 실행 단계 순서를 위아래로 재배치할 수 있어야 하고, 단계 설명 수정 기능과 API 표면을 어떻게 나눌지도 정해야 했다.

## 버린 대안

- **임의 위치로 이동(원하는 `step_order`를 직접 지정)하거나 전체 재정렬(reindex)하는 방식** — 한 번에 여러 행이 바뀌어 구현과 검증이 복잡해진다.
- **순서 이동 전용 별도 엔드포인트** — 설명 수정과 리소스가 같은데 엔드포인트만 나뉘어 중복이 생긴다.

## 결과

`PATCH /api/strategy-steps/[stepId]`는 `{ description }`과 `{ direction: 'up' | 'down' }` 두 형태를 body로 구분해 받는다. 순서 이동은 대상 단계와 인접 단계의 `step_order`만 맞바꾸므로 한 번에 인접 한 자리만 이동할 수 있고, 먼 위치로 옮기려면 여러 번 호출해야 한다. 새 단계 추가 시 `step_order`는 항상 서버가 현재 최대값+1로 부여하고, 삭제 시 뒤 단계의 번호를 당겨 빈 번호가 생기지 않게 한다.
