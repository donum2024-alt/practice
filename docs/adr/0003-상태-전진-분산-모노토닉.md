# ADR-0003 — 경쟁사 조사 상태는 각 기능이 분산 호출해 모노토닉하게 전진시킨다

## 맥락

자료 수집, 정리 확정, 벤치마킹 지점 등록이 각각 경쟁사의 조사 상태(조사중 → 자료수집됨 → 정리완료 → 벤치마킹도출)를 앞으로 올려야 한다. 반대로 정리 확정을 취소하는 등 일부 동작은 상태를 되돌릴 여지가 있다.

## 버린 대안

- **중앙 이벤트/훅이 하위 테이블 변경을 감시해 상태를 일괄 전진시키는 방식** — 기능이 늘어날 때마다 중앙 로직을 계속 넓혀야 한다.
- **확정 취소·레코드 삭제 등에서 상태를 자동으로 이전 단계로 되돌리는 방식** — 다른 경로로 이미 전진해 있던 상태까지 되돌릴 위험이 있다.

## 결과

상태 전진 판단(advanceStatus)은 `types/index.ts`의 순수 함수로만 존재하고, 호출 책임은 각 기능의 라우트(자료 등록, 정리 확정, 벤치마킹 지점 등록)에 분산된다. 자동 전진은 더 앞선 상태로만 가며, 이미 더 앞서 있으면 건드리지 않는다. 담당자는 PATCH로 상태를 자유롭게(뒤로도) 바꿀 수 있지만, 시스템이 스스로 되돌리지는 않는다.
