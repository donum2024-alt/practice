# ADR-0011 — 손자 테이블(strategy_steps)의 캐스케이드는 전용 서브쿼리로 처리한다

## 맥락

경쟁사 삭제 시 자식 테이블 삭제는 `app/api/competitors/[id]/route.ts`의 `CHILD_TABLES` 이름 목록으로 처리된다. `benchmark_points`는 competitors의 직접 자식이라 이 방식으로 걸러지지만, `strategy_steps`는 `benchmark_points`를 거치는 손자 관계라 같은 목록 방식으로는 표현되지 않는다.

## 버린 대안

- **`CHILD_TABLES`를 다단계(조인 경로 포함) 관계까지 지원하도록 일반화** — 지금 손자 테이블 하나를 위해 범용 캐스케이드 엔진을 만드는 비용이 과하다.

## 결과

경쟁사 삭제 라우트는 `strategy_steps` 건수를 `WHERE benchmark_point_id IN (SELECT id FROM benchmark_points WHERE competitor_id = ?)` 서브쿼리로 집계·삭제하는 코드를 별도로 갖는다. 앞으로 또 다른 손자 테이블이 생기면 같은 방식의 서브쿼리를 또 추가해야 한다.
