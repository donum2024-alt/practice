# ADR-0008 — 정리 문서는 5개 고정 컬럼의 단일 최신 행으로 관리하고 확정 취소는 상태를 강등하지 않는다

## 맥락

정리 문서는 경쟁사당 하나이며, 항목 구성·이력 보존 범위·확정 취소 시 경쟁사 상태 처리 방식을 정해야 했다.

## 버린 대안

- **항목을 key-value(EAV) 형태의 가변 테이블로 두어 담당자가 항목 종류를 직접 추가/삭제** — 쿼리와 화면 구성이 복잡해진다.
- **수정할 때마다 이력 레코드를 남기는 버전 관리/감사 로그 테이블** — 경쟁사당 1행이라는 단순한 모델이 깨진다.
- **확정 취소(true→false) 시 경쟁사 조사 상태를 이전 단계로 자동 되돌리는 방식** — [[0003-상태-전진-분산-모노토닉]]의 모노토닉 원칙과 충돌한다.

## 결과

`summaries`는 경쟁사당 1행, 5개 고정 텍스트 컬럼(sku_count/logistics/pricing/strengths/differentiation)만 가지며 과거 수정 내역은 보존하지 않는다. `confirmed`가 false→true로 바뀌는 순간에만 `confirmed_at`을 세팅하고 경쟁사 상태를 전진시키며, true→false(확정 취소)는 `confirmed_at`만 null로 되돌릴 뿐 경쟁사 상태는 그대로 둔다.
